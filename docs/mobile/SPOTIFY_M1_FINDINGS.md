### Detail lifecycle dan pembatalan

- `SpotifyLibraryScreen.kt:98,114-123,282-330`: Back hanya menutup komposisi login; `sent` berlaku per komposisi dan tidak ada guard eksplisit untuk callback halaman yang datang setelah Back/disconnect. `onRelease` memanggil `destroy()`, tetapi tidak menghentikan load atau melepas klien terlebih dahulu. Risiko callback terlambat perlu tes, bukan klaim crash.
- `SpotifyToken.kt:95-116,134-184`: harvest diserialkan dengan mutex dan memiliki timeout 20 detik. `catch (Exception)` pada baris 175 juga menangkap cancellation dan mengubahnya menjadi `null`; jalur pembersihan WebView ada di `finally`. Bridge menerima respons tanpa cek bahwa sesi/cookie masih sama ketika hasil disimpan. `clientToken()` dan `session()` memakai panggilan HTTP sinkron (`SpotifyToken.kt:263-308,346-383`); status 429 dalam komentar source tidak membuktikan token invalid atau keadaan server saat ini.
- `SpotifyLibrary.kt:58-70,173-199`: pagination library punya terminasi ketika halaman kosong/total tercapai; kegagalan jaringan/status dilempar sebagai exception. Tes parser yang ada hanya memeriksa dua bentuk data (`app/src/test/java/com/music/bitchord/SpotifyLibraryTest.kt:13-54`), belum menguji login, sesi, pembatalan, atau respons HTTP.

## Usulan patch terkecil untuk ditinjau (M2/M3)

1. **M2 login/lifecycle:** di `SpotifyLibraryScreen.kt`, uji UA bawaan WebView dan hilangkan CSS override **secara terpisah** pada perangkat yang mereproduksi flicker; pertahankan hanya perubahan yang memperbaiki gejala. Tambahkan penanganan error halaman/renderer dan pesan saat navigasi utama ditolak, serta guard callback setelah WebView ditutup. Pertahankan validasi scheme/host; jangan membuka login provider yang tidak mendukung embedded WebView. Tes yang diperlukan: host aman/palsu, error dan renderer termination, Back/cancel/rotasi, serta perbandingan visual terkontrol.
2. **M3 status dan race:** di `SpotifyLibraryScreen.kt`, `AccountAndScrobblingScreen.kt`, `AppSettings.kt`, dan `SpotifyToken.kt`, pisahkan `Connecting/Validating/Connected/NeedsReauth/TemporaryError` secara minimal pada alur yang ada. Jangan beri Connected sebelum operasi library yang dibutuhkan berhasil. Propagasikan `CancellationException`; ikat hasil request dan cache pada generasi/cookie yang memulainya, sehingga disconnect/pergantian akun membatalkan atau mengabaikan hasil lama. Klasifikasikan timeout/jaringan, auth nyata, dan 429 tanpa menyimpulkan semuanya sesi kedaluwarsa. Tes deterministik: cookie didapat tetapi validasi gagal, disconnect saat harvest/request, akun A→B, 401/403 versus 429 dan offline.
3. **Isolasi storage:** audit perilaku nyata `WebStorage.deleteAllData()` pada perangkat sebelum mengubah strategi harvest; target M3 ialah menghilangkan penghapusan global tanpa merusak token acquisition atau sesi WebView lain. Tambahkan tes isolasi Spotify/YouTube. Jangan menghapus seluruh cookie/WebStorage sebagai recovery.

Tunda perubahan parser/pagination/Canvas ke M4 sampai ada respons atau reproduksi spesifik. Pertahankan impor playlist dan playback. Tidak ada perubahan autentikasi besar yang disetujui: OAuth PKCE/browser adalah gate keputusan tersendiri menurut plan §4 dan memerlukan pemeriksaan dokumentasi provider, akses endpoint, scope, redirect URI, dan persetujuan eksplisit. Browser tidak menyerahkan cookie `sp_dc` WebView secara otomatis.

## Bukti runtime yang diperlukan

Untuk masing-masing gejala, diperlukan commit/APK DevDebug, model perangkat, versi Android, paket dan versi Android System WebView, metode sign-in, langkah dan waktu kejadian. Untuk crash, sertakan stack trace/logcat **tersanitasi** yang membedakan exception proses aplikasi dari renderer termination. Untuk flicker, rekaman layar serta hasil A/B UA dan CSS secara terpisah pada perangkat yang sama. Untuk login→library/Canvas, sertakan urutan tahap, kode HTTP atau kategori error tanpa body sensitif, dan hasil library serta Canvas terpisah. Untuk verifikasi identitas yang macet, cukup scheme/host navigasi dan kategori kegagalan. Jangan kirim password, OTP, cookie, token, Authorization header, HTML akun, atau URL callback lengkap.
